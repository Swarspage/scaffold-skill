# Immersive experience workflow

## 1. Establish truth before style

Read the request and existing project evidence. Write an experience brief before a scene spec. Ask only for gaps that change product truth, rights, user needs, or a material technical choice; otherwise make a clearly labeled assumption.

For a recognizable object, research comes before modelling. For an abstract object, define the intended silhouette and material behavior before adding decoration.

## 2. Choose a mode and direction

Choose the surface mode in `design-modes.md`. Turn the brief into one visual thesis using `art-direction.md`; if the brief is ambiguous, offer three genuinely different directions and wait for selection before implementation. Do not override an explicit user direction.

## 3. Build in the right order

1. Asset decision and reference pack.
2. Neutral-light silhouette check.
3. Scene spec and object hierarchy.
4. Camera and scroll narrative.
5. DOM composition and semantics.
6. Mobile and reduced-motion composition.
7. Technical verification, screenshot review, and critique.

## 4. Iterate with evidence

Batch material corrections after a review. Limit critique/fix cycles to three; then ship with known limitations or ask for a decision. Avoid polishing light, particles, or typography before the object silhouette, hierarchy, and story are credible.

## Project context

When it will help future work, create project-local `PRODUCT.md`, `DESIGN.md`, and `EXPERIENCE.md` from the templates. Review existing files first and update only confirmed or newly evidenced information.
